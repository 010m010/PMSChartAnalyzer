# Domain Docs

このプロジェクトは単一コンテキストとして扱う。用語集は Git ルート直下の `GLOSSARY.md`、設計判断の記録は `docs/adr/` に保存する。

## 調査・設計の前に読むもの

- `GLOSSARY.md` が存在する場合は、対象領域の用語を読む。
- `docs/adr/` が存在する場合は、今回の変更に関係する設計判断を読む。
- これらがまだ存在しない場合は、そのまま作業を進める。`domain-modeling` が用語や判断を確定したときに必要な文書を作成する。

## 用語と設計判断

Issue、仕様書、テスト、コードでは、用語集に定義された呼び方を使う。未定義の概念が必要になった場合は、既存の概念で表せるか確認し、必要なら `domain-modeling` で定義する。

既存の ADR と異なる方針を提案するときは、対象の ADR と変更理由を明示する。
